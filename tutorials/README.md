# Последовательный курс примеров

Установите библиотеку из корня репозитория командой
`python -m pip install ".[test,plot]"`. Каждый сценарий самодостаточен и
исполняется командой `python tutorials/имя_файла.py`. Комментарии поясняют
назначение строк; вычислительные алгоритмы находятся в C++-ядре.

| Порядок | Файл | Что изучается |
|---|---|---|
| 1 | [01_quick_start.py](01_quick_start.py) | Создание, компиляция, поиск и проверка первого расписания. |
| 2 | [02_network_csp.py](02_network_csp.py) | Нейроны, запреты, мягкие веса, сдвиги, ферзи, раскраска и сохранение динамики. |
| 3 | [03_jssp_and_tsp.py](03_jssp_and_tsp.py) | Цепочки операций на станках и направленный замкнутый маршрут. |
| 4 | [04_constellation.py](04_constellation.py) | Альтернативные аппараты, общие ресурсы и окна видимости. |
| 5 | [05_external_durations.py](05_external_durations.py) | Внешняя длительность действия, поиск над предикатом, состояние, переходы и кэш. |
| 6 | [06_resources_and_repair.py](06_resources_and_repair.py) | Память, энергия, векторный момент, квота и локальное исправление. |
| 7 | [07_multiobjective.py](07_multiobjective.py) | Необязательные заявки, генетический отбор GDS, GDE3 и фронт Парето. |
| 8 | [08_suitability_and_visibility.py](08_suitability_and_visibility.py) | Угловая видимость, исследование функции и квантование. |
| 9 | [09_visualization.py](09_visualization.py) | Самостоятельные рисунки расписания и ресурсных рядов. |
| 10 | [10_pair_constraints.py](10_pair_constraints.py) | Парная пригодность, предшествование, пропуск и непрерывные группы. |
| 11 | [11_exact_verification.py](11_exact_verification.py) | Различие предварительной и точной модели, отказы и исправление плана. |

Рекомендуется пройти примеры по порядку. Пятый пример подключает учебную
физическую функцию: для реального аппарата заменяется только адаптер этой
функции, а квантование и проверка остаются внутри библиотеки. Седьмой пример
возвращает несколько компромиссных планов; фронт Парето не определяет за
пользователя единственное предпочтительное расписание.

Все длительности `Mode` измеряются в секундах. Окна и границы `Placement`
измеряются в слотах; границы `Segment` — снова в секундах. Это различие
особенно хорошо видно в четвёртом примере с шагом десять секунд.

Каждый туториал сохраняет `schedule.png` и `resources.png` в отдельный
каталог `outputs/имя_сценария/`, исключённый из Git. В седьмом примере
внутри него создаются отдельные каталоги `genetic` и `gde3`: для каждого
метода показывается один допустимый представитель фронта Парето.
Девятый пример дополнительно сохраняет `pareto.png`.

В ресурсном рисунке загрузка, память, норма момента и накопительный запас
каждого аппарата или общего ресурса имеют собственные графики, расположенные
друг под другом. Временной шаг берётся из постановки, поэтому четвёртый
пример отображает секунды с правильным шагом десять секунд.

Во всех диаграммах расписания используется `show_labels=False`: названия
действий внутри полос выключены. Для их включения в своём сценарии
передайте `show_labels=True` в `gds_plot.gantt`.

Во втором туториале после абстрактных задач CSP добавлен пример временного
планирования через низкоуровневую сеть: именно его расписание и ресурсы
изображаются на рисунках. В третьем туториале изображается задача JSSP.
Снимок низкоуровневой сети второго примера по-прежнему сохраняется в
`outputs/network.gdsw`. Повторный запуск может перезаписать учебные результаты.
