# Интерфейс библиотеки

Заголовки C++ расположены в `include/gds`. Основное пространство имён — `gds`.
Python экспортирует те же сущности из одноимённого пакета. Английские
идентификаторы служат программными именами; описания и примеры приведены по-русски.

## Постановка и данные

| Тип или операция | Смысл |
|---|---|
| `Problem(horizon, slot_seconds=1)` | Создаёт временную сетку. Горизонт измеряется в слотах, шаг — в секундах. |
| `add_resource(Resource)` | Копирует ресурс в постановку и возвращает индекс. |
| `add_action(Action)` | Копирует заявку и возвращает индекс. |
| `add_precedence(Precedence)` | Требует начала второй заявки после окончания первой с заданными пределами разрыва. |
| `add_quota(Quota)` | Требует минимальное число выполненных заявок группы. |
| `add_contiguous_group(name)` | Запрещает включать другие группы между первой и последней заявкой группы на одной последовательной линии. Свободные интервалы разрешены. |
| `add_pair_suitability(first, second, function)` | Задаёт парную функцию, вычисляемую при компиляции. Нуль — запрет, положительное число — предпочтение. |
| `compile()` | Проверяет постановку, строит размещения и парные ограничения, возвращает независимый снимок модели. |

`Resource` содержит имя, положительную `capacity`, признак `sequence`,
предел и начальное значение памяти, начальный трёхмерный момент и предел его
нормы. `initial_level`, `minimum_level`, `maximum_level` описывают общий
скалярный запас. Начальное внешнее состояние передаётся в `initial_state`,
ориентация первой линии визирования — в `initial_pointing`. Последовательный
ресурс обязан иметь ёмкость один. Общая антенная группа с ёмкостью несколько
единиц обычно имеет `sequence=False`.

`Action` содержит `name`, `group`, список `modes`, список `windows`,
профиль `suitability`, направление `pointing`, неотрицательный `priority` и
флаг `optional`. Пустой список окон означает весь горизонт, пустая
пригодность — постоянную единицу. Несколько окон не объединяются для
размещения: действие должно целиком помещаться хотя бы в одно из них.

`Mode` задаёт основной `resource`, положительную `duration` в секундах,
список дополнительных `demands`, постоянное приращение `momentum` либо
`momentum_profile` по слотам начала, объём записи `memory`, скорость
передачи `downlink_rate` и коэффициент `remaining_momentum`. Список `flows`
задаёт изменения произвольных накопительных ресурсов.

`Demand(resource, amount=1)` добавляет постоянную потребность на весь
зарезервированный интервал. Повторное упоминание основного ресурса в этом
списке добавляет потребность к его базовой единице.
`Flow(resource, rate=0, at_end=0)` задаёт скорость изменения запаса и
однократный скачок в конце. Знак скорости может быть отрицательным.

`Window(begin, end)` измеряется в слотах. `Precedence(before, after,
min_gap=0, max_gap=-1)` связывает индексы заявок. Отрицательная верхняя
граница означает отсутствие ограничения сверху. Если вторая заявка выполнена,
первая также должна быть выполнена; пропуск второй снимает эту зависимость.
`Quota(group, minimum)` считает заявки, а не длительность их исполнения.

Структуры из pybind11 копируются при присваивании векторов. Например,
`action.modes.append(mode)` изменяет временную Python-копию списка;
правильная форма — `action.modes = [mode]`. Изменение объекта после
`add_action` не меняет сохранённую заявку. Подготовьте структуру полностью
перед добавлением. После изменения `Problem` создайте новый `CompiledProblem`.

## Скомпилированная задача

Свойство `domains` возвращает вложенный список `Placement` по заявкам.
Каждое размещение содержит `action`, `mode`, `start`, `end`, `resource`,
физическую плановую `duration`, логарифмическую пригодность и `omitted`.
Элемент `assignment[i]` — индекс в `domains[i]`, а не время начала.
Индексы могут измениться после новой компиляции.

`make_network(seed=42)` создаёт низкоуровневую сеть. Её решение можно
проверить вызовом `evaluate(network.decode_assignment())`. Передача
неверной длины либо индекса вне области вызывает исключение. Значение
`-1` допустимо для диагностического частичного плана и даёт нарушение.

`evaluate(assignment, exact=True)` возвращает `Schedule`. Список `placements`
содержит назначенные заявки, в том числе значения пропуска. `violations`
содержит вид, пояснение, индексы участников, временную область и величину
каждого нарушения. `traces` хранит загрузку, память, векторный момент и
скалярный уровень после каждого слота для каждого ресурса.

Полосы `segments` измеряются в секундах. Поле `kind` принимает `action`,
`transition` или `idle`. У перехода и действия доступны метаданные
`DurationResult`; у свободного интервала они не являются физическим
сертификатом. Только `feasible=True` при `exact=True` означает, что все
реализованные ограничения прошли окончательную проверку.

`objectives` содержит пять минимизируемых величин в фиксированном порядке,
описанном в [математическом разделе](algorithms.md). `iterations` у результата
поиска является счётчиком шагов соответствующей эвристики, а не универсальной
оценкой трудоёмкости. `stop_reason` объясняет, почему поиск завершился.

## Решатели

| Функция | Результат и назначение |
|---|---|
| `greedy(compiled, options)` | Один жадный проход; `Schedule`. |
| `min_conflicts(compiled, initial=[], options)` | Локальное исправление; пустой начальный список создаёт случайное назначение. |
| `solve_gds(compiled, options)` | Сеть, независимая проверка, запреты полных назначений и повторные старты. |
| `genetic(compiled, options)` | Популяция расписаний GDS, скрещивание, мутация, исправление и элитный отбор. |
| `gde3(compiled, options)` | Многокритериальная дифференциальная эволюция над областями размещения. |
| `dominates(left, right)` | Проверка доминирования с учётом допустимости. |
| `pareto_indices(schedules)` | Индексы недоминируемых членов; одинаковые назначения и критерии не повторяются. |

Параметры `SolverOptions`: `seed=42`, `iterations=5000`, `restarts=8`,
`repair_steps=200`, `population=20`, `generations=20`, `mutation=0.1`,
`differential_weight=0.5`, `crossover=0.9`, `momentum_balancing=False`.
Популяция должна содержать не менее четырёх членов. Вероятности находятся
между нулём и единицей, масштаб дифференциального приращения — в интервале
от нуля исключительно до двух включительно. Нулевое число поколений разрешено.

`PopulationResult` содержит `population`, `pareto_front`, `generations` и
`evaluations`. Последний счётчик относится к внешним членам эволюционного
поиска; внутренние проверки GDS и локального исправления в него не входят.
Если допустимых членов нет, фронт содержит недоминируемые недопустимые планы.
Вызывающая программа обязана проверить их `feasible`.

## Стандартные задачи

`make_jssp(machines, horizon, jobs)` принимает последовательность работ,
состоящих из `Operation(machine, duration)`. В этой форме длительности
измеряются в слотах; шаг равен одной секунде. Машина каждой операции задана
заранее, последовательность операций создаёт предшествование.

`make_parallel_jobs(machines, horizon, durations, capacity=1)` создаёт
независимые работы с альтернативным выбором любого аппарата. При ёмкости
больше единицы аппарат становится общим ресурсом без единственной цепочки
физического состояния. Для неодинаковых аппаратов используйте явные `Mode`.

`make_tsp_network(costs, seed=42)` использует квадратную матрицу направленных
неотрицательных стоимостей. Положительная бесконечность означает отсутствие
дуги. Число городов должно быть не меньше двух. `tour_cost(tour, costs)`
проверяет перестановку и учитывает замыкание цикла. `solve_tsp` возвращает
`TourResult` с маршрутом, стоимостью, признаком допустимости и числом шагов.

## Низкоуровневое ядро

`GDSNetwork(num_variables, domain_sizes, ...)` задаёт конечную CSP.
Параметры динамики доступны как свойства: `beta`, `w_forbidden`,
`gamma_same`, `guard_bias`, `guard_delta`, `guard_phi`, `max_iterations`,
`stop_rule`, `seed`. Поддерживается только пороговая активация
`binary_threshold`, обновление `guarded_discrete_stochastic` и начало
`all_off`; другие строки отклоняются, а не молча игнорируются.

`add_forbidden_pair` и `add_weighted_pair` добавляют связи; после серии
добавлений требуется `finalize_weights`. `set_unary_bias` задаёт сдвиг
одного нейрона. `set_unary_biases(biases)` принимает плоский массив сдвигов
всех нейронов и пересчитывает входы один раз; длина и конечность значений
проверяются до изменения сети. `add_nogood` запрещает полное назначение. Методы
`set_assignment`, `set_state`, `get_state`, `get_state_matrix`,
`get_inputs`, `get_guard_state` позволяют исследовать динамику.

`step` возвращает `StepInfo`: строку, нейрон, прежнее и новое состояния,
оценку рассогласования и счётчики. `run` возвращает `RunResult`.
`StopRule.MAX_ITERATIONS` продолжает динамику до лимита,
`SATISFIED_OR_MAX_ITERATIONS` останавливается при выполнении ограничений.
`reset_state_all_off` обнуляет состояния и счётчики, сохраняя положение
генератора случайных чисел; для повторения начала также установите `seed`.

`save_weights(path)` и `load_weights(path)` сохраняют и восстанавливают
параметры, связи, индивидуальные сдвиги, полные запреты, состояния, счётчики
и генератор в формате `GDSW2`. Прежний неполный формат `GDSW1` не загружается.
Снимок сети не содержит описание расписания, внешние провайдеры или кэш;
соответствие индексов размещениям хранит вызывающая программа.

## Численные утилиты и графики

`duration_slots`, `quantize_interval`, `sample_slot`, `log_suitability`,
`radec_to_unit`, `angular_separation`, `angular_visibility` реализованы
на C++. Углы задаются в градусах. Положения тела и наблюдателя должны быть
выражены в одной системе координат и одних единицах; эфемериды библиотека
не загружает. Пустой ряд наблюдателя означает начало координат.

`sample_slot` возвращает минимум, максимум, среднее по трапециям и признак
большой относительной изменчивости. Это выборочная оценка, а не доказательство
отсутствия узкого запрета между узлами. `quantize_interval` поддерживает
`cover`, `inside`, `nearest`; последний округляет половины от нуля по
правилу C++ `std::round`.

Пакет `gds_plot` отдельно предоставляет `gantt`, `resource_traces` и
`pareto`. Они возвращают оси Matplotlib и не изменяют расписание.
Основной пакет `gds` не импортирует графические зависимости.

`gantt(schedule, problem, ax=None, *, show_labels=True)` возвращает одну
область рисования расписания. Именованный параметр `show_labels=False`
убирает названия действий внутри временных полос. Названия ресурсов,
подписи осей и заголовок остаются видимыми. Во всех туториалах текст
внутри полос отключён именно этим параметром.

`resource_traces(schedule, slot_seconds=1.0, resource=None, axes=None,
problem=None)` по умолчанию показывает все ресурсы расписания. Для каждого
ресурса создаются четыре графика: загрузка, память, норма момента и
накопительный запас. Все графики расположены вертикально; величины
не совмещаются на одной области рисования. `resource=0` позволяет выбрать
один ресурс. Передача `problem` задаёт названия ресурсов из постановки;
шаг в секундах следует передать через `slot_seconds=problem.slot_seconds`.

Возвращается кортеж осей в порядке ресурсов, внутри каждого ресурса —
в указанном порядке четырёх величин. Общий рисунок доступен как
`resource_axes[0].figure`. Прежнее распаковывание результата в две оси
памяти и момента больше не применяется. При передаче собственных осей
через `axes` нужно заранее создать четыре различные вертикальные области
для каждого выбранного ресурса.
