Локальная проверка выполнена 21 сентября 2026 года на Linux с GCC 13.3.0,
CMake 3.28.3, CPython 3.12.3, pybind11 3.1.0 и scikit-build-core 1.0.3.
Ниже перечислены исполняемые проверки, а не требования к будущей работе.

масштабируемости на промышленную спутниковую группировку.

## Что именно проверяют тесты

Маленькая задача JSSP перебирается полностью. Для каждого назначения
результат встроенной проверки сравнивается с независимо записанными
условиями пересечения и предшествования. Проверки ферзей сравнивают
столбцы и диагонали напрямую, а направленный TSP проверяет замыкающую дугу
и отсутствие недопустимых рёбер.

Специальный пример с тремя потребителями и ёмкостью два показывает,
почему парной допустимости сети недостаточно. Полный проверяющий модуль
отвергает этот план, а готовый решатель не сообщает ложный успех.
Другие проверки контролируют последовательность записи и освобождения
памяти, знаки векторов момента, разгрузку, временной профиль момента,
скалярный запас, квоты, непрерывность групп и общий канал двух аппаратов.

Внешние модели проверяются на монотонном и немонотонном предикатах,
на неизвестных ответах и исключениях, начальном переходе, передаче состояния,
кэше, изменении длительности после предыдущего действия и отказе точной
модели после успешного приближения. Отдельный пример подтверждает допустимость
A→B→C при невозможности прямого A→C.

Эволюционные проверки сравнивают воспроизводимость одинакового зерна,
размер популяции, недоминируемость выданного фронта и повторную проверку
всех результатов. Вручную заданные векторы критериев и разноимённые
нарушения проверяют отношение доминирования независимо от решателя.

## Как повторить проверки

```bash
python -m pip install ".[test,plot]"
python -m pytest -q
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
for script in tutorials/*.py; do python "$script"; done
python -m pip install build
python -m build
python tests/check_distribution.py
```

Для локальной сборки без изолированного получения зависимостей заранее
установите `scikit-build-core`, `pybind11` и `ninja`, затем используйте
`python -m build --no-isolation`.

```bash
cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer"
cmake --build build-sanitize --parallel 2
ctest --test-dir build-sanitize --output-on-failure
```

Автоматическая проверка GitHub задаётся в `.github/workflows/ci.yml`.
Она собирает самостоятельное ядро и запускает Python-проверки и учебные
сценарии на версиях 3.10, 3.12 и 3.13. Фактический статус конкретного
коммита следует смотреть в разделе Actions репозитория.

## Границы результата

Готовые решатели не гарантируют глобальную оптимальность. Превышение
лимита итераций не является доказательством отсутствия решения. Численные
эксперименты из статей JWST и DSAN не воспроизводились: миссионных
массивов и соответствующих физических симуляторов в исходных материалах нет.

Внешняя физика в тестах задаётся детерминированными учебными провайдерами.
Реальная интеграция с телеметрией, SOAP или моделью конкретного аппарата
должна подтвердить собственный контракт состояния, времени и сертификата.
Производительность больших задач, одновременный доступ к одной модели
из нескольких потоков и аппаратные испытания не входят в выполненную
локальную проверку. Семантика этих ограничений подробно описана в
[документе внешних длительностей](external_durations.md).
