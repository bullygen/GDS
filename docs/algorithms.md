# Математическая постановка и методы решения

## Конечная задача размещения

Пусть горизонт состоит из слотов с номерами от нуля до (T-1\), а длительность
слота равна \(\Delta t>0\). Заявке \(A_i\) сопоставляется конечное множество
размещений \(D_i\). Элемент этого множества содержит способ исполнения,
аппарат, начальный слот \(s\) и конечный слот \(e\). Занятым считается
полуоткрытый интервал \([s,e)\), поэтому окончание одного действия может
совпадать с началом следующего.

Длительность в секундах переводится в целое число слотов по правилу

\[
L=\lceil d/\Delta t\rceil,\qquad e=s+L.
\]

Начало перебирается в каждом способе исполнения. Размещение включается в
\(D_i\), если оно целиком принадлежит одному заданному окну, не выходит за
горизонт, не требует больше полной ёмкости ресурса и не пересекает нулевую
пригодность. Области значений строятся в `CompiledProblem` на C++.
Если заявка необязательна, к области добавляется отдельное значение пропуска.
Отрицательный индекс назначения означает незаполненную строку и всегда
рассматривается как нарушение; его нельзя использовать для допустимого пропуска.

Удобно ввести двоичные переменные
\(y_{iv}=1\), если выбрано размещение \(v\in D_i\). Индекс \(v\) содержит
координату времени и, при наличии альтернатив, номер аппарата. Таким образом,
одна строка сети соответствует одной заявке, а не одному временному слоту.
Представление охватывает обычное поле «временной слот — номер действия» и
расширяет его дискретными способами исполнения.

Положительная индивидуальная пригодность усредняется в логарифмической шкале
по занятому интервалу:

\[
\ell_{iv}=\frac1{e-s}\sum_{t=s}^{e-1}\log S_i(t).
\]

Нуль \(S_i(t)\) исключает размещение. Значение `log_suitability(evidence)`
является отдельной утилитой: она возвращает логарифм произведения свидетельств;
при нуле результат равен минус бесконечности. При компиляции нулевые значения
обрабатываются до вычисления логарифма.

Пользовательская парная функция через `add_pair_suitability` вычисляется при
компиляции для всех пар размещений выбранных двух действий. Нулевой результат
создаёт жёсткий запрет, положительный — логарифмическую мягкую добавку.
При пропуске хотя бы одного действия парная функция не вызывается.
Функция должна быть чистой относительно описания задачи и возвращать конечное
неотрицательное число. В C++ она задаётся через `std::function`; Python может
передать внешний вызываемый объект через pybind11.

## Сеть GDS

Сохранённое ядро реализует дискретную стохастическую сеть с отдельным охранным
нейроном для каждой строки. При числе активных значений \(n_i\) его состояние
равно

\[
g_i=\mathbf1\{b_g-\delta n_i\geq0\}.
\]

Вход основного нейрона имеет вид

\[
x_{iv}=\beta+b_{iv}+\varphi g_i+
\sum_{jw}W_{iv,jw}y_{jw}.
\]

В одной строке разные значения взаимно тормозят друг друга с весом
\(-\gamma\). Для явно запрещённой пары добавляется вес \(-w_f\), причём
сам запрет отдельно сохраняется в проверяющей структуре. Произвольный большой
положительный вес не может отменить проверку жёсткого запрета. Допустимость
проверяется по ограничениям, а не по величине энергии.

На каждом шаге равновероятно выбирается строка. Среди её нейронов,
состояние которых не согласуется со знаком входа, меняется нейрон с наибольшим
модулем рассогласования. Равенство оценок разрешается случайно. Нулевой вход
считается разрешающим включение. При изменении состояния пересчитываются
входы соседей и охранный сигнал. Глобального спуска одной энергии обещать
нельзя: охранная обратная связь делает динамику отличной от обычной симметричной
сети Хопфилда.

В построителе расписаний индивидуальный сдвиг равен \(\tanh\ell_{iv}\),
а мягкая парная связь равна гиперболическому тангенсу суммы логарифмов парных
пригодностей. Ограниченное преобразование удерживает шкалу входов сопоставимой
со стандартными охранными параметрами; окончательный критерий качества
использует исходные логарифмы. Это инженерная нормировка данной реализации,
а не утверждение о точном воспроизведении всех параметров исторической SPIKE.

`GDSNetwork.is_satisfied()` проверяет единственность значения в каждой строке,
состояние охранных нейронов и явные запреты. Метод не знает про память аппарата,
общую ёмкость трёх потребителей и внешнюю физическую модель. Высокоуровневый
решатель вызывает `CompiledProblem.evaluate()` после каждого полного кандидата.
Отклонённое назначение \(v_1,\ldots,v_n\) превращается в ограничение

\[
\prod_i y_{i,v_i}=0.
\]

Оно хранится как запрет полного назначения. Вход соответствующего нейрона
получает штраф, если все остальные члены этого произведения активны.
Подмножества назначения остаются допустимыми. Это существенно для физических
переходов, зависящих от соседства и предыстории. При наличии таких запретов
после изменения состояния выполняется полный пересчёт входов.

## Независимая проверка ресурсов

Для каждого ресурса \(r\) и слота \(t\) вычисляется загрузка

\[
q_r(t)=\sum_{i:s_i\leq t<e_i}q_{ir},\qquad q_r(t)\leq C_r.
\]

Основной ресурс способа исполнения получает единичную потребность;
дополнительные `Demand` суммируются с ней. Два непересекающихся действия не
конфликтуют. При ёмкости больше единицы одной проверки пар недостаточно,
поэтому проверяется полная сумма всех одновременно активных действий.

Запись данных производится в конце действия. Перед записью в каждом слоте
вычитается объём передачи данных; память не может стать отрицательной:

\[
M_{t+1}=\max(0,M_t-\Delta t\sum_i r_i(t))+\sum_{i:e_i=t+1}m_i.
\]

Момент хранится вектором. Сначала применяется произведение коэффициентов
остаточного момента завершающихся разгрузок, затем суммируются приращения:

\[
\boldsymbol H_{t+1}=\left(\prod_{i:e_i=t+1}\alpha_i\right)\boldsymbol H_t
+\sum_{i:e_i=t+1}\Delta\boldsymbol H_i(s_i).
\]

`momentum_profile` задаёт зависимость приращения от слота начала. Если профиль
не задан, используется постоянный вектор `momentum`. Контролируется евклидова
норма после каждого слота, включая промежуточные максимумы. Начальный вектор
проверяется уже при компиляции. Здесь не реализуется динамика отдельных
маховиков: она относится к подключаемой внешней модели.

Накопительный скалярный ресурс изменяется на сумму скоростей `Flow.rate`,
умноженных на шаг сетки, и скачков `Flow.at_end`. После каждого слота
проверяются нижний и верхний пределы. Этим способом описываются энергия,
топливо либо иной аддитивный запас. Список участников нарушения включает
предшествующие действия, повлиявшие на запас.

## Жадный поиск и исправление конфликтов

Жадный метод сначала упорядочивает заявки по приоритету и размеру области.
При включённой балансировке он предварительно выделяет наблюдения,
уменьшающие суммарный момент. Затем для очередной заявки перебираются её
размещения и выбирается лучшее по независимой оценке частичного плана.

В локальном исправлении каждому действию приписывается сумма величин
нарушений, в которых оно участвует. Выбирается действие с наибольшей такой
суммой; равенство разрешается случайно. Его область перебирается полностью.
Сравнение сначала предпочитает допустимость, затем меньшее число нарушений,
меньшую их суммарную величину и лексикографически меньший вектор критериев.
С вероятностью 0,08 вместо лучшего размещения делается случайный шаг.
Лучший найденный план сохраняется отдельно, поэтому неудачный шаг его не теряет.

`solve_gds` выполняет заданное число повторных стартов. После исчерпания
итераций текущей сети запускается локальное исправление её назначения.
Результат содержит причину остановки. Эти методы эвристические: они не
доказывают оптимальность и не устанавливают неразрешимость при исчерпании бюджета.

## Балансировка момента

Реализован критерий `find_reducers` из работы Giuliano, Rager, Ferdous 2007 года.
Для заданного временного интервала сначала вычисляется
\(\boldsymbol H_\Sigma=\sum_i\Delta\boldsymbol H_i\). Кандидат относится
к уменьшающим момент, если

\[
\|\boldsymbol H_\Sigma+\Delta\boldsymbol H_i\|-\|\boldsymbol H_\Sigma\|<0.
\]

Важно именно повторное прибавление вектора кандидата к общей сумме, как в
процедуре статьи. Обычная минимизация нормы отдельного приращения является
другой эвристикой. Для нескольких временных интервалов пользователь передаёт
в `find_reducers` соответствующие каждому интервалу векторы. Готовый жадный
старт использует постоянные векторы первых способов исполнения. При нескольких
аппаратах или временных профилях интервальную классификацию следует задавать
раздельно; этот простой старт не заменяет физическую оценку всего расписания.

## Многокритериальный поиск

Все пять критериев минимизируются: сумма приоритетов пропущенных заявок;
суммарный простой последовательных аппаратов, включая края горизонта;
сумма пиковых норм момента по ресурсам; отрицательная сумма логарифмической
пригодности; суммарная длительность, стоимость и риск переходов.
Единицы последних двух добавок задаёт внешний модуль, поэтому для осмысленной
суммы он должен заранее нормировать их в согласованной шкале.

Допустимый план превосходит недопустимый. Для двух допустимых планов
используется строгое доминирование Парето: каждый критерий первого не хуже,
а хотя бы один строго лучше. У недопустимых планов формируется вектор сумм
величин нарушений отдельно по каждому виду ограничения; компоненты разных
видов не складываются при проверке доминирования.

Генетический метод создаёт исходную популяцию независимыми запусками GDS.
Родители выбираются двоичным турниром по недоминируемому рангу и расстоянию
скученности. Скрещивание выбирает каждое назначение с равной вероятностью у
одного из родителей. Мутация заменяет его случайным значением области.
Потомки проходят локальное исправление. Родители и потомки объединяются,
после чего сохраняются лучшие слои; последний неполный слой сокращается по
расстоянию скученности. Крайние точки непостоянного критерия имеют бесконечное
расстояние; постоянный критерий не вносит вклад.

GDE3 хранит непрерывные векторы \(x\in[0,1]^n\), отображая каждую компоненту
в индекс конечной области размещения. Для родителя выбираются три различных
донора, отличных от него. Пробный вектор имеет вид

\[
u=x_{r_1}+F(x_{r_2}-x_{r_3}).
\]

Выполняется покомпонентное скрещивание с вероятностью `crossover`, причём
хотя бы одна компонента обязательно берётся из пробного вектора. Выход за
границы устраняется ограничением на \([0,1]\). Если оба плана допустимы и
несравнимы, сохраняются оба; если один доминирует, сохраняется он. Для двух
недопустимых потомок принимается только при слабом покомпонентном доминировании
в пространстве нарушений. Увеличенная популяция сокращается по рангам и
расстоянию скученности, как в исходной схеме GDE3.

Дискретное декодирование и набор критериев являются адаптацией к общей
постановке библиотеки. Это не повторение численных экспериментов JWST или
DSAN: их исходных физических моделей и массивов наблюдений в репозитории нет.
Поворот вокруг линии визирования можно представить альтернативными `Mode`
с различными профилями момента; отдельный непрерывный оптимизатор ориентации
внутрь библиотеки не встроен.

## Вычислительная стоимость

Пусть \(D=\sum_i|D_i|\). Построение парных ограничений требует в общем случае
\(O(\sum_{i<j}|D_i||D_j|R)\) проверок ресурсов и памяти для сохранённых
связей. Внутри строки ядро хранит все связи взаимного торможения. Независимая
проверка ресурсов имеет стоимость \(O(TRN)\). Локальное исправление
вызывает её для каждого пробного значения выбранной переменной.

Текущий вариант рассчитан на конечные задачи умеренного размера. Окна и
разумный шаг сетки уменьшают области до компиляции. Разреженные временные
индексы, параллельный расчёт популяции и распределённое исполнение не заявляются.
Зависимые от истории физические ответы кэшируются по полному запросу, но
один объект `CompiledProblem` нельзя одновременно использовать из нескольких
потоков без внешней синхронизации.
